## 觸發本次模擬的事件

**2026-05-04（Sprint-18 第一天）**：

設計師 Emma 提案「重建 design token 系統」。當前痛點：
- Design tokens 只有 semantic 層（如 `--color-primary`），沒有 primitive 層（如 `--blue-500`）
- 換主題（dark mode 即將上線）時要改 30+ 處 semantic token 各自的 primitive 值
- 設計師 Fang 反映加新顏色時不知道該命名為 semantic 還是直接用原色
- 工程師 Chen 在實作 dark mode prototype 時抱怨 token 結構難以擴充

Emma 想推「dual-tier semantic + primitive」架構，但：
- 改動會觸及 ARCHITECTURE.md 的「設計系統」章節（**禁改清單**）
- 影響全部既有元件（30+ 個）
- Sprint 已排定 Q3 OKR 主題，加這個會擠掉其他

她在週日晚 push 了一份草稿到 raw/，週一早 Alex 開 Claude 看到後，啟動 round-table。

## 模擬將驗證的設計

| 設計機制 | 模擬驗證方式 |
|---|---|
| Role agent 並行（避免 anchor bias） | 9 個 agent 同時提案，看分歧是否真的浮現 |
| 紅線一（重大決策必走同步軌） | sync-guard 攔截 Emma 想直接改 ARCHITECTURE.md |
| 紅線二（design-review 不能跳過） | sre BLOCKS 後 Emma 必須 rev2 才能合併 |
| 紅線三（容量同步可視） | people-ops 標記 Fang 已 90% 容量，建議重排 |
| 同步軌 ⇄ 個人軌雙軌 | David 在 individual focus 中發現硬編碼 → 透過 /sync-context 回流觸發新議題 |
| medium mode 的 tech-lead vs engineer | tech-lead 在 round-table 出場，poll 組內 Chen/David 意見 |
